# Stitch MCP — Cursor setup (AgentEval)

Use this so the agent can call Stitch (`list_projects`, `generate_screen_from_text`, `get_screen`, etc.) instead of you copy-pasting prompts manually.

## Security (read first)

1. **Never commit API keys** to git. Use Cursor MCP env vars or a local `mcp.json` that is gitignored.
2. If a key was pasted in chat or Slack, **rotate it** in Google Cloud / Stitch settings and use the new key only in env.
3. Add `STITCH_API_KEY` to `.env` (already gitignored) for your own reference; Cursor MCP env is separate.

## Fix: `@google/stitch-mcp` is not a valid npm package

`npx -y @google/stitch-mcp` returns **404** on npm. Use one of these instead:

### Option A — Remote Stitch MCP (API key) — try this first

Copy `.cursor/mcp.json.example` → `.cursor/mcp.json` and set the key via **Cursor Settings → MCP → stitch → Environment**, or paste the header value in Cursor’s MCP UI if it supports headers.

```json
{
  "mcpServers": {
    "stitch": {
      "url": "https://stitch.googleapis.com/mcp",
      "headers": {
        "X-Goog-Api-Key": "YOUR_KEY_HERE"
      }
    }
  }
}
```

Some users report **“API keys are not supported”** on the remote endpoint; if so, use Option B.

### Option B — OAuth proxy (recommended if Option A fails)

From [davideast/stitch-mcp](https://github.com/davideast/stitch-mcp):

```bash
npx @_davideast/stitch-mcp@latest init
npx @_davideast/stitch-mcp@latest doctor
```

Cursor config (generated by `init`):

```json
{
  "mcpServers": {
    "stitch": {
      "command": "npx",
      "args": ["-y", "@_davideast/stitch-mcp@latest", "proxy"],
      "env": {
        "GOOGLE_CLOUD_PROJECT": "YOUR_GCP_PROJECT_ID"
      }
    }
  }
}
```

Enable API: `gcloud services enable stitch.googleapis.com --project=YOUR_PROJECT_ID`

## Enable in Cursor

1. Place config in **Cursor → Settings → MCP** (user or project `.cursor/mcp.json`).
2. **Reload window** (or restart Cursor).
3. Confirm **stitch** shows green / tools listed.

## Agent workflow (once MCP is connected)

The agent will:

1. `list_projects` → find or `create_project` named **AgentEval SaaS**
2. For each screen in [STITCH_PROMPTS.md](STITCH_PROMPTS.md), call **`generate_screen_from_text`** with `project_id` + prompt body
3. `list_screens` / `get_screen` → optional `get_screen_code` / export for `web/` reference
4. Refine one change per follow-up generation (Stitch best practice)

**Canonical onboarding stepper (aligned with your latest mock):**

1. Name agent  
2. Requirements & endpoint  
3. Preview pack  
4. Freeze suite  
5. Run & CI gate  

**Product constraints** (every generation): pre-release testing only, not chat UI, not prod APM; demo `demo-refund-agent`, $100 cap; Python CLI `pip install agenteval` not npm.

Ask the agent: *“List Stitch projects via MCP.”*  
If tools are missing, MCP is not loaded — fix config and reload.
